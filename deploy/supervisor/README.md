# Native parser supervisor candidate

This directory contains an inactive host-side supervisor for the pinned native parser candidate. It is not enabled by the application deployment. It owns only the two parser `runc` instances, their private OCI bundles, cgroup directories, pidfds, and the dispatcher handoff/status socket directory. It never reads source documents, jobs, databases, application secrets, or parser payloads.

The accepted boundary remains in the dispatcher. This process starts a worker in `created` state, validates its host PID, UID/GID, PID namespace, cgroup membership and resource files, then sends exactly one pidfd to the root-owned dispatcher handoff socket. It calls `runc start` only after the exact ACK and a fresh `handed_off` status for the same dispatcher epoch, role and handoff ID. It waits for the dispatcher to report `reaped`; it separately requires the pidfd to be exited and the cgroup to be empty before issuing `runc delete` or removing that run's bundle/cgroup. A process exit or expired lease can precede its fresh `reaped` publication: the supervisor waits at most five monotonic seconds for that exact handoff, without cleanup, replacement or lease extension. Repeated polls never extend this deadline. Stale, malformed, red, mismatched, or inaccessible status still fails immediately and never authorizes cleanup. The supervisor does not kill workers to force cleanup.

## Pinned candidate

`native-ingest-supervisor.json` is an exact, immutable configuration checked against the same constants in the Python module. It binds the OCI archive, OCI manifest/config, all eight layers, worker artifact, Java entrypoint, `/app` image working directory, worker JAR, runc binary, sandbox profile, two role UIDs, observation profiles and resource limits. The config installed at `/etc/knowvault/native-ingest-supervisor.json` must be root-owned mode `0600`; changing one field makes startup fail closed. The OCI `Config.WorkingDir` is verified as `/app`, and the OCI process starts in `/app`.

The archive and runc executable are installed offline at the configured paths as root-owned, non-group/world-writable regular files. The rootfs is prepared offline from that exact OCI archive by the separately qualified release packaging process. This supervisor does not download, unpack, or update images. The installed `/opt/knowvault/native-ingest-v3/rootfs.identity.json` must be a root-owned mode `0444` file with this exact schema:

```json
{
  "schema_version": "knowvault-native-parser-rootfs-v1",
  "oci_archive_sha256": "024b7e44021154a024af07caf246917b93913686a19f25a1d47a9351c75be16d",
  "oci_manifest_digest": "sha256:bf1e580938eb62a05de1efe2cdf24d7fc8ab9339e5224be238f3794a0c9e0855",
  "oci_config_digest": "sha256:8006f7ddf504af8aee59afea5fcc719f673d7df80f6717c2ffced6b428c8d467",
  "artifact_hash": "sha256:ccea6413429e0fb69d64d6065c15453fa432b9ac38e8399363ce455111eca414",
  "rootfs_tree_sha256": "57f844763873eb9bd9896938ba89beaad459da1eb62fbf154c30602f983c5e7d"
}
```

`rootfs_tree_sha256` is generated by the offline qualification/release process, not by the running service. It hashes every rootfs entry without following symlinks. Each entry is represented by canonical ASCII JSON (sorted keys, compact separators) containing its relative path, mode, uid, gid and type; regular files also include size and SHA-256, while symlinks include their literal target. The digest input is the concatenation of a four-byte big-endian record length and each canonical record. The running service recomputes this digest and independently verifies `/app/artifact.sha256`, the worker JAR and executable Java path. It fails before opening the handoff socket if any pin or tree value differs.

`prepare_native_rootfs.py` prepares a fresh output directory offline from the pinned archive. It rejects traversal, writes through symlinks, whiteouts, hardlinks and unsupported entry types. It preserves file bytes, ownership, permission bits and relative symlinks; timestamps do not enter the tree identity. The archive's supported layer subset contains 166 entries / 88,832,087 file bytes. Packaging also creates empty, root-owned mount targets for `/proc`, `/dev`, `/tmp` and `/run/knowvault`; occupied or unsafe targets are rejected. This allows runc to mount its private filesystems without writing to the runtime rootfs. Two independent preparations on Linux produce the tree digest above and the committed `rootfs.identity.json`. The supervisor pins that digest independently of the identity file, so replacing both a worker and its identity document is refused.

```text
sudo python3 -B /opt/knowvault/supervisor/prepare_native_rootfs.py --archive /path/to/pinned/parser.oci.tar --output-dir /path/to/fresh/root-owned/output
```

The output parent must already be root-owned and not group/world-writable. An error leaves a failed staging directory for diagnosis; it must not be installed. Packaging creates no services, cgroups or containers and performs no downloads.

## Host installation contract

For the limited pilot, install all four units persistently under
`/etc/systemd/system` and enable both the preparation and supervisor services.
The preparation service runs after local filesystems/tmpfiles and before
`sysinit.target`, so the Docker worker's host bind-mount directory exists with
the required mode before normal application services start. It retains its
15-second bound and refuses invalid existing directory metadata. No Docker or
other application's unit is modified. Validate the installed unit graph with
`systemd-analyze verify` before enabling. A KnowVault-only stop/start with fresh
socket directories can exercise this sequence without rebooting a shared host;
that drill is not evidence that a full host reboot has been tested.

Install the Python file, JSON config, unit files, and dispatcher drop-in from a reviewed release package as root-owned immutable files. The host requires Python 3, systemd 254 or newer (`DelegateSubgroup`, qualified on 255), unified cgroup v2, pidfd support, and the exact verified `/usr/bin/runc` executable. No package download or OCI pull is performed by these units. The bounded `knowvault-native-supervisor-prepare.service` runs the pinned Python entrypoint with `--prepare-only` before either the main supervisor or dispatcher starts. It creates only the six canonical directories below; it never chmods or repairs existing directories. Existing symlinks, wrong owner/group, or wrong modes cause startup failure. The main supervisor rechecks their owner, group, mode and inode before each status read and worker launch. The units use umask `0022` so traversal modes survive directory creation; runc itself runs with umask `0077` to create a private PID file.

* `/run/knowvault` and `/run/knowvault/sandbox`: root:root mode `0755`;
* `/run/knowvault/sandbox/supervisor`: root:root mode `0700`, for `handoff.sock` and `status.json`;
* `/run/knowvault/sandbox/submit`, `/run/knowvault/sandbox/office` and `/run/knowvault/sandbox/pdf`: root:root mode `0711`, for the separate submit and registration sockets. The supervisor prepares/verifies directory metadata and never opens the submit socket.

The main supervisor unit is ordered before `knowvault-dispatcher.service`; the dispatcher drop-in requires and binds its lifetime to the supervisor. If the supervisor fails or stops, systemd stops the dispatcher so its existing teardown closes admission. The separate preparation unit completes before both. `KillMode=mixed` and `SendSIGKILL=yes` retain manager-first graceful termination and provide an emergency kill of the service's remaining parser descendants after manager death or the bounded stop deadline. This OS fence does not authorize any result or runtime cleanup. The supervisor's private runc/bundle runtime directory is preserved across service stop/failure. Existing bundles, runc state, or any child cgroup directory under the dedicated cgroup parent cause startup to fail closed; the service never guesses which stale resources it may remove. Resolve such state using the host incident procedure after independently proving the matching process and cgroup are gone.

The service lives in `knowvault_native.slice` and delegates CPU, memory and pids controllers at the **service**, not slice, level. `DelegateSubgroup=supervisor` keeps the manager in a leaf. Workers are direct `kvp-office-*` and `kvp-pdf-*` children of `/sys/fs/cgroup/knowvault_native.slice/knowvault-native-supervisor.service/parsers`. The manager creates and enables only this delegated subtree. The per-worker limits remain 10% of one CPU, 64 MiB and 16 processes, within the aggregate service bounds. Do not bind-mount a cgroup child over itself through the supervisor's `ReadWritePaths`: the qualified runc rejects that mount crossing. `ProtectSystem=strict` excludes the kernel API filesystems; the code pins its own delegated paths.

On the qualified systemd 255 host, `User=root` with `NoNewPrivileges` left `CAP_SETUID` in the bounding set but absent from the effective set. The unit explicitly retains `AmbientCapabilities=CAP_SETUID` for runc's transition to the fixed parser UID. Every parser capability is still dropped by the OCI spec. The host reopens `/usr/bin/runc`, verifies its pinned digest and original device/inode/size/mtime immediately before every command, then executes through that already-verified file descriptor. Only `runc state` captures stdout; `create` uses `/dev/null` because its stopped init inherits stdio and would otherwise hold the parent's pipe open before the handoff.

The included `knowvault-dispatcher.service` is the host qualification candidate for the existing fourth Go binary; it has no database, application secrets, network configuration or container runtime. Host qualification now covers real create/handoff/registration, sequential DOCX/PDF/XLSX jobs, wrong submitter identities and graceful shutdown while OFFICE is BUSY and PDF READY. Both services finish successfully, the interrupted client receives no result, and runc state, bundles and parser cgroups are empty. SIGKILL of either manager while READY or BUSY also leaves no parser processes or successful interrupted result; preserved stopped runtime entries block restart. An additional cgroup fault injection confirms termination of a SIGTERM-ignoring parent/child pair. Operator requirements and limits: [native document ingestion](../../docs/NATIVE-INGEST.md). The remaining negative cases, delivery incident tooling and release packaging remain open. This directory is not activated by application deployment.

## Local checks

The source has standard-library tests only:

```text
python3 -m py_compile deploy/supervisor/native_ingest_supervisor.py deploy/supervisor/test_native_ingest_supervisor.py
python3 -m unittest discover -s deploy/supervisor -p "test_*.py"
```

The rootfs descriptor walk and layer tests run on POSIX. Linux Python 3.12.3 passes 28 tests without skips; two clean preparations, modified-worker rejection and forged-identity rejection also pass. Receipt: `.local/release/native-rootfs-qualification-1789477582927/`. These unit/packaging checks are separate from the host lifecycle receipt.
