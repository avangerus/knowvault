Always answer a question and keep simple questions quick

The tool loop could end a Question Run with a fixed "could not be
completed within the configured profile limits" text even when no limit
had been hit, discarded every verified claim as soon as one citation
failed, showed overview questions the slow multi-step path, and answered
Russian questions with English caveats.

Give the loop one forced submit-only turn after its mounted budget that
can only answer from what was already gathered: every normal-turn ending
(tool-call or step budget, time budget, context or output limit, provider
failure, repeated format error) now continues to that turn instead of
returning, its answer goes through the same citation verification, and
only when it also fails does the user see a failure text. That text names
what happened and which sources were consulted, and mentions a limit only
when one was really reached.

Keep the claims whose citations verified and drop the ones that did not,
recording the dropped-citation claims and a UNVERIFIED_CITATIONS
uncertainty instead of replacing the whole answer. The displayed bytes
are always exactly the kept claims, and ClaimEvidence binds them through
a new VerifiedClaims index list (absent on older v1 records, read as the
identity mapping).

Answer workspace-overview and greeting questions from a compact overview
read before the first model turn: source lines with type, status and
object counts, a few inventory rows with citable fragment addresses and
the workspace context description, capped at two research tool calls.
The overview travels as its own user message, never in the trusted system
message, and reuses the single pinned workspace-context read.

Finally, put every user-visible fallback, uncertainty and failure text in
the language of the question: the tool-loop texts, the Russian
uncertainty dictionary that still held English sentences, and an English
dictionary selected on read from the run's own question.

Verified with go build/vet, the internal suites, the architecture guard,
and the PostgreSQL integration suite (full run plus the new scripted
scenarios: forced answer, failed forced turn, partial verification with
one and two claims in both orders, overview with zero tool calls, and the
Russian/English fallback pair).
